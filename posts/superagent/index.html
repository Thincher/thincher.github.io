先去掉常规的技术
常规技术先拆出去,聚焦核心。
异步 ReAct
run → start/stop,本质是后台进程 + 轮询 + kill。Claude Code 的 BashOutput、Codex 的 background exec 同款。
存算分离
云上无状态 loop、会话状态入库。Devin、Codex cloud、Cursor cloud agent 都在做。
Watchdog
对应 supervisor / critic / termination-check 那一族,本质是 agent 监控 agent。
subagent 续接
opencode 的 task_id、Claude Code 的 SendMessage 带 agent ID、Codex 的 resume_agent_from_rollout 都能沿用原会话。

Router 如何保证转发准确性
1
注入质量
从「ID + 摘要」起步,按局部性 Inline 前后文、所回复的那条、相邻评论;超预算就 Spill,留续读入口。目的是降低判断难度,不必自己读一遍。
2
外化记忆
对象都有唯一 ID,注入时内联下一跳的 ID,底层连成引用图按需展开。持有句柄,不持有数据,即链式召回。
3
归属外置
订阅关系存数据库,不在 Router 上下文里。它只判「要不要开新任务」,比判「属于谁」简单一个量级。
4
允许判错
Worker 可退订交回、同一 Thread 多人订阅会在执行侧暴露冲突、Watchdog 从外部判方向。闭环兜住中心节点的判断质量。
